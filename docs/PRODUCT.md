# 产品说明

> 星皓书房（Xinghao Library）是一个 **Calibre 驱动的自托管个人数字图书馆**。
> Calibre 负责藏书与元数据，本站负责「把书读好」——阅读器体验对标 Koodo Reader。

本文回答四个问题：为谁做、解决什么、和谁比、先做什么。

- 证据时点：2026-10-28
- 证据来源：talebook 源码与 `spec/`、Koodo Reader 官网与仓库、Calibre 官方文档、Calibre-Web / Kavita / BookLore / Komga / Readest 官方仓库，以及本项目已发布的静态站实现

## 1. 定位

| 项目 | 结论 |
|---|---|
| 目标用户 | 个人书虫与家庭 / 小圈子共读；用户自己就是管理员，通常部署在 NAS 或 VPS |
| 核心任务 | 把已有的 Calibre 书库变成一个**读得下去**的网站 |
| 不做什么 | 不做公共书库运营、不做书源爬虫、不做 DRM 破解、不托管无授权内容 |
| 形态 | 单进程 Web 应用：Python 后端 + 零构建前端，Docker 一条命令启动 |
| 与静态站的关系 | `星皓书房` 静态站（Hugo + GitHub Pages）是零成本展示面；本应用是完整形态 |

一句话取舍：**talebook 的功能面 + Koodo 的阅读面 + Calibre 的数据面。**

## 2. 角色与任务

| 角色 | 核心任务 | 当前替代方案 | 摩擦点 |
|---|---|---|---|
| 管理员（通常就是读者本人） | 藏书、整理元数据、部署升级、备份 | Calibre 桌面端 + 手动传文件 | Calibre 的阅读器观感差；换设备要重新找书 |
| 读者 | 找书、读、记笔记、换设备继续 | Koodo（导入麻烦）、微信读书（书不在库里） | 进度与笔记散落在多个工具 |
| 家庭成员 | 浏览共享书架、读、留下自己的记录 | 共用一个网盘账号 | 没有「谁读到哪」的概念 |
| 访客 | 看看有什么书 | — | 需要可控的只读入口 |

## 3. 产品闭环

```
Calibre 库（metadata.db + 书文件）
   │  只读，不迁移、不改写
   ▼
书架发现（封面墙 / 搜索 / 筛选 / 排序 / 最近在读）
   │
   ▼
阅读（分页 · 主题 · 字体 · 目录 · 全文搜索 · 快捷键 · 手势）
   │
   ▼
记录（进度 · 书签 · 划线 · 笔记）→ 存本站自有库
   │
   └──► 下次打开任意设备，回到原处
```

断点优先级：**状态不一致 > 不可恢复错误 > 发现效率 > 新能力**。

## 4. 竞品对照

| 维度 | 星皓书房 | talebook | Koodo Reader | Calibre-Web | Kavita | BookLore | Komga |
|---|---|---|---|---|---|---|---|
| 数据源 | Calibre 库只读 | Calibre 库 | 自行导入 | Calibre 库 | 自有扫描 | 自有扫描 | 自有扫描 |
| 定位 | 个人 / 家庭 | 多用户书库 | 跨端阅读器 | Calibre 前端 | 漫画 + 电子书 | 现代书库 | 漫画为主 |
| 阅读器 | 主线，对标 Koodo | 嵌入式 candle-reader | 强 | 基础 | 中 | 中 | 中 |
| 转换 / 推送 | 路线图（调用 Calibre CLI） | 有 | 无 | 有 | 无 | 部分 | 无 |
| 多用户 | 路线图 | 有 | 账号云同步 | 有 | 有 | 有 | 有 |
| 部署成本 | 单容器，无 Node 构建 | 多容器 + Nginx | 客户端 | 单容器 | 多容器 | 多容器 | 单容器 |
| 与 Calibre 关系 | 不侵入，Calibre 仍是唯一写入方 | 混合 | 无关 | 不侵入 | 无关 | 无关 | 无关 |

**借鉴（做）**

- talebook：统一阅读入口与格式优先级（EPUB → PDF → TXT）、阅读状态四组语义互不覆盖、笔记私有默认、书库筛选与回收站思路。
- Koodo：阅读器信息架构——左侧目录/笔记抽屉、底部进度、独立的排版设置面板；主题与字体即时生效。
- Calibre-Web：只读挂载 Calibre 库，避免双写冲突。

**差异化（做出优势）**

1. **零迁移**：指向已有 Calibre 目录即可用，书和元数据都不动。
2. **阅读器是一等公民**：不是「能打开」，而是「愿意一直用」。
3. **零构建部署**：没有 Node 构建链，镜像小、升级快，NAS 友好。
4. **静态书房导出**：把书库一键导出成可托管在 GitHub Pages 的静态站（已先行实现）。

**不进入（明确拒绝）**

- 书源爬虫与盗版聚合、DRM 绕过、公共书库运营。
- 在 Web 端重做 Calibre 的元数据编辑全量能力（交给 Calibre，Web 端只做轻量修正）。
- 自建客户端 SDK（桌面端交给 Moke / Readest / KOReader，通过协议对接）。

## 5. 优先级与路线

| 阶段 | 内容 | 状态 |
|---|---|---|
| M0 静态书房 | Hugo + GitHub Pages 书架与书籍页 | 已发布 |
| **M1 阅读优先 MVP** | Calibre 只读接入、封面墙、详情页、Koodo 级 EPUB 阅读器、进度/书签/划线笔记 | **本轮实现** |
| M2 管理与格式 | 上传入库、格式转换（Calibre CLI）、元数据轻编辑、回收站、PDF 阅读器 | 计划 |
| M3 多用户与生态 | 账号与权限、OPDS、设备推送、跨端进度合并 | 计划 |
| M4 打磨 | 全文搜索索引、统计、推荐、静态站导出、TTS | 计划 |

**M1 验收条件**

1. 指向任意 Calibre 库目录即可启动，不需要任何预处理。
2. 书架能正确展示作者、系列、标签、评分、简介、格式与封面。
3. 打开 EPUB 后：目录可跳转、主题/字号/行距/页边距即时生效、刷新后回到原位置。
4. 划词可高亮并写笔记，刷新后高亮仍在。
5. 桌面键盘（←/→/Esc）与移动端触摸翻页可用。
6. `docker compose up` 一条命令在 NAS 上跑起来。

**风险与待验证**

| 风险 | 影响 | 对策 |
|---|---|---|
| Calibre schema 版本差异（5.x / 6.x / 7.x） | 元数据读取失败 | 只读取稳定表，缺失表自动降级；启动时打印 schema 探测结果 |
| 大库（>1 万本）列表性能 | 首屏慢 | 服务端分页 + 索引；必要时加重建缓存 |
| epub.js 对复杂排版（竖排、固定版式）支持有限 | 部分书显示异常 | 检测 `rendition.layout === 'pre-paginated'` 时切换为图片式翻页 |
| 家庭多用户进度冲突 | 覆盖他人进度 | 进度按（用户, 书）存，M3 前默认单用户 |
| 版权 | 法律风险 | 只托管用户自有内容；仓库只含公版书演示库 |

## 6. 度量

M1 只观测三条，不编造基线：

- 打开阅读器到首屏可读的时间。
- 阅读会话中进度写入成功率（应为 100%，失败即缺陷）。
- 划线笔记的持久化成功率。
